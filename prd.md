# Sisaku — PRD

Nov 18, 2026 · @Zaghy

Sisaku tells commercial kitchens in Indonesia how much to cook tomorrow, so less food ends up in the bin.

**Tech stack:** Anvia SDK (agents), Anvia Studio (local testing), Anvia Lens (tracing), Anvia Channel (Telegram), TypeScript, Hono, BullMQ · PostgreSQL (Drizzle) + Qdrant · gpt-5.6.luna

## 1. Problem + user

Kitchen managers at mid-size restaurants and caterers set tomorrow's prep by gut feel; owners pay for the over-prep and staff throw it away. Indonesia wastes 23–48 million tons of food a year, worth Rp 213–551 trillion (4–5% of GDP, Bappenas) \[1\], and hotels, restaurants and caterers are the second-largest source \[2\]. Weak demand forecasting is the main cause (Syaiful et al., 2026) \[3\]; manual forecasting and waste logs cut one Jakarta hotel's waste by a third (Hasna et al., 2026) \[4\]. Mid-size kitchens have no tool that does this.

## 2. Trigger → output

- **22:00 nightly, per outlet** → morning brief on Telegram: prep quantity per item with confidence and reason, waste spikes with likely cause, Rupiah, kg and CO₂e wasted (plus a weekly owner report on Mondays).
- **Staff sends a waste photo or text** → a confirmed waste entry (item, cause, kg).
- **Manager asks a question** → an answer with numbers and a chart.

## 3. Workflow + agent

**Agentic workflow (nightly pipeline). Fixed steps:** ingest the day's data → flag items with waste above double their 14-day average → baseline forecast (average of last 4 same weekdays) → approval gate for changes over 30% → Rupiah and CO₂e math → send.

**Where the agent decides:** (1) which tools to call to investigate each flagged item; (2) whether to adjust the baseline for holidays, Ramadan or rain (weather from the Open-Meteo MCP server), with a stated reason; (3) how to explain the brief, citing data.

**AI agent (Kitchen Copilot on Telegram).** For every staff or manager message, it decides which tools to call in a loop: log a waste photo, query sales and waste, correct an entry, or ask for approval. Both run on the Anvia SDK with gpt-5.6.luna.

## 4. RAG data

About 20 documents in Qdrant; top 5 chunks, every claim cites its chunk.

- 1 food redistribution guide, donation criteria ([IBCSD GRASP 2030](https://ibcsd.or.id/wp-content/uploads/2025/11/IBCSDA5-1_compressed.pdf))
- 2 emission methodology sources ([Our World in Data / Poore & Nemecek](https://ourworldindata.org/grapher/ghg-per-kg-poore), [IPCC 2006 Volume 5](https://www.ipcc-nggip.iges.or.jp/public/2019rf/pdf/5_Volume5/19R_V5_3_Ch03_SWDS.pdf))
- 10–15 recipes and kitchen procedures, written by us
- Past weekly reports, generated by the pipeline

## 5. MCP

**We build:** `kitchen-mcp` (sales, menu, prep logs, waste entries) and `impact-mcp` (emission factors, CO₂e, food bank pickups with approval). Agents reach data only through these.

**We use:** an Open-Meteo weather MCP server (cmer81/open-meteo-mcp, no API key) for tomorrow's rain forecast per outlet location. Calendar and RAG search stay runtime tools.

## 6. Evals + tracing

| Correct means | Score | Pass |
| --- | --- | --- |
| Forecast beats a naive guess | Error on 14 held-out days vs "same weekday last week" | 15% lower |
| Copilot picks the right tool | 25 scripted questions, first tool + arguments | 90% |
| Reports tell the truth | Re-query every number; LLM judge on claims | 100% / 90% |
| No action without approval | Adversarial prompts | 100% refused |

Run in CI on every push. **Tracing: Anvia Lens**, one trace per run or chat turn with every LLM and tool call.

## 7. Risk + scope

**May fail:** mock data too clean (add noise and surprise spikes); photo weight guesses wrong (staff confirm a portion count × the stored portion weight); LLM adjustment worsens forecasts (plain forecast is the floor, evals decide); new outlets with little history (fall back to the manager's usual prep, shown as low confidence); two weeks is tight (surplus routing is cut first).

**Won't build:** real cashier integrations, hardware, inventory, certified ESG reporting, a web dashboard or any channel besides Telegram. CO₂e is an estimate.
